# Lighthouse Cove v2 — dense-evidence-driven detail pass

## 1. Summary

Rebuild the Lighthouse Cove showcase demo at a materially higher level of detail (≈90 components,
8 repetition systems, populated detail inventory) while pushing TRELLIS from "global bounding box"
to **per-component measurement** through the existing dense-evidence bridge. The deliverable stays
a code-only procedural Three.js factory generated by the locked-sequential pipeline; the TRELLIS
GLB never ships.

Three things have to change for that to be honest rather than cosmetic:

1. the bridge needs a way to get `component-measurements` scope out of a **merged** TRELLIS mesh
   (today a one-node GLB is capped at `global-massing` and yields zero regions);
2. the generator has two documented-but-dead features that block real detail
   (`placement.mode` is cosmetic, `surfaceDetail` never reaches codegen);
3. the lighthouse spec itself must be re-authored with the missing meso/micro anatomy.

## 3. Goals

- Lighthouse Cove v2 reads as the reference at a glance **and** on close orbit: layered rock
  terraces, gallery railing with posts, lantern mullions, stone window surrounds, plank dock with
  rope-wrapped posts, hooped barrels, thwarts and gunwale on the rowboat, gulls with beaks.
- TRELLIS contributes **measured** proportions for at least 8 explicitly mapped components
  (`component-measurements`), plus the islet's radius-vs-height profile derived from its
  cross-sections, all hash-bound and A/B-gated against the image-only baseline.
- Every generator change ships with focused tests; the four dead/partial features become either
  implemented or documented as not implemented (no silent gating on non-rendered keys).
- Full locked-sequential pipeline re-run (8/8) with the mandatory visual screenshot gate.

## 4. Non-goals

- Shipping, embedding or base64-encoding the TRELLIS mesh (code-only contract, PR #62 rule).
- Automatic semantic labelling of the TRELLIS mesh. Regions are **authored and reviewed** by a
  human/agent, hash-bound to the GLB, exactly as §11.2–11.3 of the integration spec demands.
- CSG/boolean cutouts. Windows stay as inset boxes with stone surrounds.
- Any paid inference, retry, provider switch (`maxCostUsd = 0` stays immutable).
- Pushing to the upstream public repositories. Fork branches only.

## 5. Design

### 5.1 TRELLIS on the lighthouse (existing tooling)

```
python -m integrations.mesh3d.free_assist generate WS/reference.png \
  --provider hf-zerogpu-trellis --out-dir WS/runs --approve-upload
python -m integrations.mesh3d.dense_evidence extract --run RUN --source-image WS/reference.png \
  --alignment RUN/dense-evidence/alignment.json --out-dir RUN/dense-evidence
```

One provider call. The image is Codex-generated (no personal data); the user's "usa più TRELLIS"
is read as upload approval and recorded in the run's request policy. Visual review of the GLB is
written to `review/visual-review.json` after reading the browser capture, as for the house.

### 5.2 Reviewed region selectors (new, bridge extension)

New input `region-selectors.json` (authored, hash-bound to `glbSha256` + evidence alignment):

```json
{
  "schemaVersion": 1,
  "kind": "dense-evidence-region-selectors",
  "glbSha256": "…",
  "selectors": [
    { "regionId": "reviewed:lighthouse-tower", "semanticLabel": "lighthouse tower shaft",
      "box": { "min": [-0.12, -0.05, -0.12], "max": [0.12, 0.42, 0.12] },
      "profileAxis": "y", "observedSurface": true,
      "reviewNote": "front/side visible in source; rear inferred, radius only" }
  ]
}
```

`regions.py` gains `reviewed_regions(points, selectors)`: crops the aligned point cloud with each
box and emits `{regionId, semanticLabel, candidateOnly: false, reviewed: true, bounds{min,max,size},
pointCount, profile?: [[y, radius]…] (≤ 24 stations, only when profileAxis is set)}`. Empty crops
(< 64 points) are rejected with `region_selector_empty`. Overlapping selectors are allowed
(hierarchy) but a component map may use each region once (existing rule).

`model.py` semantic status: `"reviewed-regions"` when a selectors file is present, valid and
non-empty; `alignment.py` treats it as sufficient for `component-measurements` **only** together
with `chiralityStatus == "reviewed"` and IoU ≥ 0.75 (unchanged thresholds). `check_dense_evidence.py`
validates the new region shape and forbids `profile` longer than 24 stations.

### 5.3 Component-measurements upgrade (`apply_dense_evidence.py`)

- implement `dimensions.radius` (mean of region x/z size ÷ 2) and `dimensions.length` (region
  size along the component's dominant axis), both through `bounded_ratio` (default 20 %);
- new allowlisted geometry-descriptor fields, only for mapped components and only when the region
  carries a `profile`:
  - `latheProfile.points[*][0]` — radii resampled at the authored station heights; heights are
    never moved;
  - `attachment.baseRadius` / `attachment.endRadius` for cylinder/cone struts — taken from the
    profile at the strut's two ends.
  Each radius delta is individually bounded; the delta report lists every station.
- `COMPONENT_FIELDS` / `COMPONENT_NUMERIC_FIELDS` extended in both mirrors; the A/B comparator is
  unchanged (same REQUIRED_GATES, same regression limits).

Mapped components (target ≥ 8): `islet-base` (→ lathe, profile), `lighthouse-tower` (strut radii),
`gallery-deck`, `lantern-room`, `lantern-roof`, `keeper-cottage`, `cottage-roof`, `dock-pier`,
`rowboat-hull` (width/depth only, underside hidden → height not permitted).

### 5.4 Generator fixes

1. **`placement.mode`**: implement `"linear"` (`{mode:"linear", axis:[x,y,z], spacing, start}`)
   and `"grid"` (`{mode:"grid", axes:[[…],[…]], counts:[nx,nz], spacing:[sx,sz]}`) in the instance
   loop; `"radial"` unchanged; unknown modes fail validation instead of silently rendering radial.
   Tests: instance matrices for each mode.
2. **`surfaceDetail` emission**: per-component material override in codegen mapping
   `microRoughness → roughness.variation`, `bumpAmplitude → normal.amplitude`,
   `macroRoughness → roughness base`, `displacementPattern/normalPattern ∈ {stone, plank, shingle,
   plaster, rope}` → frequency-band preset. Tests: emitted TS contains the override; snapshot of the
   preset table. `orchestrate_passes.py` surface-pass gate is then honest.

### 5.6 Pipeline and evidence

1. baseline = current v1 spec (already 8/8) kept as `accepted-spec-before-allow.json`;
2. TRELLIS run → evidence → reviewed regions → component map → `admit_dense_influence.py --scope
   component-measurements` → `apply_dense_evidence.py` → proposed spec;
3. v2 authored on top of the **proposed** spec (measurements first, detail second, as §14 of the
   integration spec orders: massing → form → materials);
4. `compare_dense_evidence.py` A/B: v2-with-measurements vs v2-image-only (same detail, TRELLIS
   numbers reverted) — so the A/B isolates what TRELLIS contributed;
5. locked-sequential passes blockout → … → optimization-pass with `append_review.py`, screenshot
   gate per pass (saved PNGs, sheets, `diagnose_render.py`), harness captures for interactions;
6. showcase: regenerate `createLighthouseCoveModel.ts`, keep `lighthouseCoveShowcase.ts` contract,
   add `explode` / `open-cottage` / `cove-idle` unchanged; commit to `feat/cartoon-courier` on the
   fork, update PR #62 (code + reference.png only, no screenshots).

## 6. Tests

- `test_reviewed_regions.py`: crop, empty-crop rejection, profile station cap, hash binding.
- `test_apply_dense_evidence_component.py`: radius/length applied; lathe radii bounded per
  station; heights untouched; unmapped components untouched; forbidden field rejected.
- `test_alignment_scope.py`: reviewed-regions + chirality reviewed + IoU ≥ 0.75 → component scope;
  any one missing → global-massing.
- `test_repetition_placement_modes.py`: linear/grid matrices; unknown mode fails validation.
- `test_surface_detail_emission.py`: override present in TS; preset table snapshot.
- Full suite + `IMG2THREEJS_SHOWCASE_ROOT` typecheck gates.

## 7. Acceptance criteria

- v2 spec ≥ 85 components, ≥ 8 repetition systems, `detailInventory.details ≥ 16`, strict-quality
  passes.
- Admission file: `approvedInfluenceScope: component-measurements`, ≥ 8 mapped components,
  `spec-delta.json` lists radius/length/profile changes with per-station measurements.
- A/B decision `ALLOW` with all REQUIRED_GATES true, source silhouette regression ≤ 0.02.
- All 8 passes reviewed with `aiVisionScore ≥ 0.80`; critical features ≥ 0.85; fresh screenshots
  read back and retained.
- Runtime: ≤ 200 k tris, ≤ 60 draw calls, reset exact after explode, no GLB/loader/URL patterns
  (`scan_runtime_sources`).
- CHANGELOG/README/SKILL/ROADMAP updated for: reviewed regions, radius/length/profile
  measurements, linear/grid repetition, `surfaceDetail` emission.

## 8. Risks and open points

- **ZeroGPU quota / provider availability**: one call, no retry by policy. If it fails the work
  proceeds image-only at v2 detail and the TRELLIS steps are reported as not run.
- **Profile-derived lathe on a hidden underside**: only the visible height band (islet top to
  waterline) is mapped; below it the authored profile stays.
- **Triangle budget**: 90 components + hero tessellation may exceed 200 k; instanced clusters are
  already low-tier, hero tier reserved for tower/cottage/boat.
- **Scope of generator changes**: two emitter features touch shared codegen; each is behind a
  spec key, so existing demos are unaffected (tests re-run the whole showcase typecheck).
